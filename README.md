# max30003_node – MAX30003 ECG front end on NUCLEO-U385RG-Q

The STM32U385 reads ECG samples from the MAX30003 test board (Arduino Uno
headers), runs the R-peak detector from the Prosjektoppgave (`rdetect`) on
10 s blocks, and sends the R-peaks and the pulse to the PC over the ST-LINK
virtual COM port. Built from `firmware/ecg_node/ecg_node.ioc` in the
Prosjektoppgave: same clock tree (MSIS 96 MHz), same TIM3 FCLK and same BSP
setup (VCP on USART1, USER button, D7 power-monitor trigger).

## Layout

```
max30003_node.ioc     STM32CubeMX project, open and regenerate as usual
Core/Inc, Core/Src    CubeMX files + application code:
  max30003.c/.h         register-level MAX30003 driver (SPI, FIFO burst read)
  max30003_config.h     MAX30003 settings: gain, filters, EFIT, RtoR, test signal
  ecg_acq.c/.h          INTB/INT2B interrupts, double-buffered sample blocks
  uart_tx.c/.h          non-blocking printf: ring buffer sent from the USART1 interrupt
  ecg_stream.c/.h       paced ECG + heart rate stream for a serial plotter (ECG_STREAM)
  main.c                detector loop and report to the PC (USER CODE sections)
rdetect/              the energy R-peak detector, copy of c/rdetect
tools/ecg_live.py     PC side: live plot of the ECG_STREAM output (ECG, HR, R-peaks)
tools/ecg_monitor.py  PC side: print the block report (ECG_STREAM=OFF), log peaks to CSV
Drivers/, cmake/      HAL, CMSIS, BSP and CMake files as generated by CubeMX
```

## Pins (MAX30003 test board → Nucleo)

| Board net | Arduino | STM32 | CubeMX setting / label |
| --- | --- | --- | --- |
| FCLK  | D9  | PC6 | TIM3_CH1 PWM, `MAX_FCLK`, 96 MHz / 2930 = 32.765 kHz |
| CSB   | D10 | PC9 | GPIO output, high at start, `MAX_CSB` |
| MOSI (SDI) | D11 | PA7 | SPI1_MOSI |
| MISO (SDO) | D12 | PA6 | SPI1_MISO |
| SCLK  | D13 | PA5 | SPI1_SCK (master, mode 0, 8 bit, 6 MHz) |
| INT0 (INTB)  | D3 | PB3 | GPIO_EXTI3 falling, pull-up, `MAX_INTB` |
| INT1 (INT2B) | D2 | PC8 | GPIO_EXTI8 falling, pull-up, `MAX_INT2B` |
| ASIG  | A2  | PA4 | free, for DAC1_OUT1 (see below) |
| 3V3, GND | power header | | |

- PB3 was SWO in `ecg_node`; it is INTB here, so debugging is SWD only (PA13/PA14).
- SPI1 moved from slave (USB-ISS feeder) to master; SPI2, GPDMA1 and SPI1_NSS on PA4 are gone.
- The green LED LD2 shares D13 with SCLK, so it flickers during transfers.

## Changing pins in CubeMX

The application code only uses the CubeMX labels (`MAX_CSB_Pin`,
`MAX_INTB_Pin`, `MAX_INTB_EXTI_IRQn`, `MAX_INT2B_*`, `PWR_TRIG_*`) and the
handles `hspi1` / `htim3`. Moving a signal therefore only needs the label
kept on the new pin:

- INTB / INT2B: any pin as `GPIO_EXTIx`, falling edge, with the EXTI line
  interrupt enabled in NVIC. Two lines must not share an EXTI number.
- CSB: any GPIO output, initial level high.
- FCLK: any timer channel giving 32.768 kHz PWM. If it is not TIM3 CH1,
  change `htim3` / `TIM_CHANNEL_1` in `HAL_TIM_PWM_Start()` in `main.c`.
- SPI: another SPI instance needs `&hspi1` in `ecg_acq_init()` changed.

Everything written by hand is in `USER CODE` sections or in files CubeMX does
not touch, so regenerating keeps it.

## Build and flash

Open the folder in VS Code (STM32Cube extension) or:

```
cmake --preset Debug
cmake --build --preset Debug
```

The VS Code task `Flash` writes `build/Debug/max30003_node.elf` with
STM32_Programmer_CLI.

## Build options (CMake)

| Option | Default | Effect |
| --- | --- | --- |
| `ECG_STREAM` | ON | one line per sample with ECG and heart rate, for a serial plotter |
| `TTK8_LOOPBACK` | OFF | run the TTK8 loopback test (`ttk8_test.c`) instead; does not return |

CMake keeps option values in its cache, so an existing `build/` folder keeps
the old ones: delete it, or configure with e.g. `-DTTK8_LOOPBACK=OFF`.

## Live stream (`ECG_STREAM=ON`, 115200 baud, ST-LINK VCP)

```
max30003_node: 200 sps, 10 s blocks
ECG stream: ecg:<uV>,hr:<bpm>,r:<0|1> per sample, 11.0 s behind
MAX30003 ready (INFO 0x5x3xxx)
ecg:-12,hr:0.0,r:0
...
ecg:1043,hr:72.3,r:1
```

- `ecg`: the ECG in µV at the input (LSB = 1 V / (2^17 · gain)).
- `hr`: beat-to-beat heart rate, 60 · fs / RR, updated at every R-peak that
  rdetect found and held until the next one. 0 before the first interval and
  after 3 s without a beat.
- `r`: 1 on the sample of an R-peak.

rdetect works on whole 10 s blocks, so the stream runs a fixed 11 s behind
(one block plus 1 s for the detector, `ECG_STREAM_MARGIN_SAMPLES`). Each
detected block is copied into a playback ring and sent out at exactly the
sample rate: playback is paced by the acquisition sample counter
(`ecg_acq_count()`), not by SysTick, which is stopped while the MCU sleeps.
Lines leave in groups of EFIT = 16 (every 80 ms), about 3 kB/s, a quarter of
what 115200 baud carries.

`python tools/ecg_live.py` plots the ECG with its R-peaks and the
heart rate on separate axes (needs `pyserial`, `matplotlib`; `--csv` logs every
sample). Any plotter that reads `label:value,label:value` lines works too, such
as the Arduino IDE 2 Serial Plotter, but the heart rate (≈70) then shares an
axis with the ECG (≈1000 µV).

### Running the plotter on a Mac (or any PC)

Only Python is needed; the firmware can be built and flashed elsewhere. Plug
the Nucleo's ST-LINK USB into the Mac, then from the repository folder:

```
python3 -m venv .venv
source .venv/bin/activate
pip install -r tools/requirements.txt
python tools/ecg_live.py
```

The script finds the ST-LINK port itself (`/dev/cu.usbmodem…` on macOS,
`/dev/ttyACM…` on Linux, `COMx` on Windows). `--list` shows the ports and
`--port /dev/cu.usbmodem14103` picks one. Next time only `source
.venv/bin/activate` and the last line are needed. On Windows the activate step
is `.venv\Scripts\activate`.

VS Code reports errors all over the C code on a machine without the ARM
toolchain and a configured CMake build (no `arm-none-eabi-gcc`, no
`build/Debug/compile_commands.json` for clangd). They are editor errors only
and do not matter for running the plotter.

### Why output never blocks

All output goes through `uart_tx`: `printf` (via `_write`) and the stream
copy bytes into a 4 KB ring, and the USART1 TX interrupt (priority 3, below
INTB/INT2B at 2) sends them using the 8-byte TX FIFO. The main loop never
waits on the UART character by character, the MAX30003 interrupts can run at
any time during output, and nothing is printed from an interrupt. The stream
checks for room before each line and waits for the next wake-up instead of
blocking. The main stack is 4 KB (`_Min_Stack_Size` in the linker scripts);
it was 1 KB, which newlib `printf` plus a nested INT2B/SPI interrupt could
overflow.

## Block report (`ECG_STREAM=OFF`, 115200 baud, ST-LINK VCP)

```
max30003_node: 200 sps, 10 s blocks
MAX30003 ready (INFO 0x5x3xxx)
rtor 832 ms, 72.1 bpm
block 0 @ 0: 2000 samples, 12 peaks, pulse 72.3 bpm: 143 309 475 ...
```

- `block k @ first`: block number and the running index of its first sample.
- Peaks are running sample indices at 200 Hz since start (seconds = index / 200).
- `pulse` is 60 · fs / median RR over the block, including the interval from
  the last peak of the previous block. `-` when there is no interval.
- `rtor` lines come from the MAX30003's built-in R-to-R detector on INT2B, one
  per beat, for comparison (`MAX30003_RTOR_ENABLE`).
- Pressing USER restarts at sample 0 and pulses D7, as in `ecg_node`.

`python tools/ecg_monitor.py --port COM5 --csv peaks.csv` prints the same lines
and logs every peak.

## Settings

- `Core/Inc/max30003_config.h`: gain (default 20 V/V), 0.5 Hz high-pass,
  40 Hz low-pass, resistive bias, lead-off detection, FIFO threshold (EFIT 16),
  RtoR on INT2B, and `MAX30003_USE_CAL_SIGNAL` which feeds the internal ±0.5 mV,
  1 Hz square wave to the channel to test the chain without an input signal.
- `ECG_ACQ_BLOCK_SECONDS` in `Core/Inc/ecg_acq.h`: detector block length,
  10 s by default, up to 60 s (`RDETECT_MAX_SAMPLES`). 60 s uses 155 kB RAM.
- `rdetect/rdetect_config.h`: the detector, unchanged from the Prosjektoppgave
  (200 Hz). The build stops if the two sample rates disagree.

## Notes

- 200 sps is CNFG_GEN.FMSTR = 10 with CNFG_ECG.RATE = 10. FCLK from TIM3 is
  107 ppm low, plus the MSIS tolerance, so the true rate is about 199.98 sps.
  Locking MSIS to the LSE crystal on the Nucleo would make it exact.
- Samples are read in the INTB interrupt, so the detector can run in the main
  loop without losing samples; the main loop sleeps with WFI between events.
  Stop modes would stop TIM3 and with it FCLK.
- Test signal (`Core/Src/ecg_sim.c`): DAC1 OUT1 on PA4 (A2 → ASIG) plays a
  synthetic ECG (P-QRS-T, R = 10 mV) on a 0.9 V baseline at 60 bpm, stepped
  from the 1 kHz TIM6 interrupt. Put JP1 on ASIG and JP2 on 0V9. Each USER
  press restarts acquisition and steps the rate 60 → 75 → 90 → 120 → 45 bpm.
  Settings in `Core/Inc/ecg_sim.h`; `ECG_SIM_ENABLE 0` leaves PA4 off.
